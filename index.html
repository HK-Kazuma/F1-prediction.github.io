背景と参考リポジトリ

参考リポジトリ
github.com/ryoma193tclt/f1-regulation-compare-chatbot
FIA 2025/2026 テクニカルレギュレーションを比較・解説するRAGチャットボット。LightRAG + LangGraph + FastAPI + Streamlit 構成。本プロジェクトの技術的出発点。

このリポジトリのLightRAG資産（PDF解析・ハイブリッド検索）をそのまま流用することで、レギュレーション情報をF1順位予測に組み込むというアイデアに発展した。

3つのアイデア

1
Idea 01

データ分析ベース
ML順位予測

FastF1 / OpenF1 で走行データを取得し、XGBoost でレース毎の1〜20位を出力する最小構成。予選順位・タイム・天候・サーキット特性を特徴量として使用。

FastF1 OpenF1 XGBoost scikit-learn FastAPI Streamlit
OUTPUTレース毎の予測順位（1〜20位）
2
Idea 02

レギュレーション有利度スコア統合

FIA規則PDFをLightRAG + LLMで解析。規定タイプを分類し、チームDNA×規定の相性スコアをアイデア1の特徴量に追加。規定変更年の開幕前でも有利チームを推定可能。

LightRAG LangGraph LLM 規定タイプ分類 チームDNA PDF解析
OUTPUT規定×チーム有利度スコア → アイデア1の特徴量へ
3
Idea 03

ベイズ更新 / モンテカルロ
チャンピオンシップ予測

レースが終わるたびにベイズ更新でモデルを修正し、残りシーズンをモンテカルロで1000回シミュレーション。アイデア2のスコアを事前確率として使用。

ベイズ更新 Monte Carlo partial_fit 確率分布
OUTPUTチャンピオンシップ確率の動的更新

レイヤー構造

3つは独立したシステムではなく、1→2→3の順で積み重なるパイプラインとして設計する。

03
チャンピオン予測
ベイズ更新 + モンテカルロ

アイデア2のスコアを事前確率として初期化。レース結果が出るたびに更新し、残りシーズンの確率分布を可視化。シーズン後半ほど精度が上がる。

02
定性→定量変換
LightRAG + LLM スコアリング

FIA規則PDFを解析して規定タイプを分類し、過去の同タイプ年でのチーム成績と紐付けてスコア化。アイデア1に特徴量として渡す前処理レイヤー。

01
予測エンジン
XGBoost 順位予測

走行データ（FastF1）＋レギュレーションスコア（アイデア2）を受け取りレース毎の順位を出力。MVPはこのレイヤーだけで動かせる。

精度への影響：シナリオ別

通常年（過去データあり）

アイデア1単独でも十分機能する。予選順位の相関が高くXGBoostは安定して上位を当てられる。アイデア3を加えるとシーズン後半の誤差補正が効く。

レギュレーション変更年（2026年）

アイデア1は過去データが別規定のものになり精度が大幅低下。アイデア2の規定タイプ分類×チームDNAスコアが開幕序盤の空白を補完する。最も効くユースケース。

シーズン中盤〜終盤

アイデア3が最も輝く局面。実績が積まれるほどベイズ更新の精度が上がり「残り5戦で逆転できる確率は何%か」という出力が意味を持ち始める。

規定変更年でも予測できる理由

「規定変更年は予測不能」は正確ではなく、「今まで使っていた特徴量が効かなくなるだけで、別の特徴量に切り替えれば予測できる」が正しい。

# 規定タイプ別スコアリングの実装イメージ
regulation_type = "ground_effect_aero"  # LLMで分類

# 過去の同タイプ規定年でのチーム平均順位
historical_score = {
    "Red Bull":  avg_position_under(regulation_type),
    "Mercedes":  avg_position_under(regulation_type),
    "Ferrari":   avg_position_under(regulation_type),
}

# このスコアをXGBoostの特徴量として注入
features["regulation_dna_score"] = historical_score[team]
規定変更の状況予測精度への影響
規定変更 × チームDNAと相性がいい予測可能（例：2022年のRed Bull）
規定変更 × 完全に新技術（前例なし）不確実性は高いが適応速度指標で補える
当日環境（雨・気温）チーム別の過去環境データで対応可能

開発方針

目的
データ分析 × ML を学びながら作る

コードには「なぜこう書くか」の解説コメントを付与し、可読性を優先する。精度の数字より「なぜその精度なのか説明できる状態」にすることを重視する。

精度イメージ
MLB勝率グラフのように動的に収束

シーズン序盤は幅広、終盤になるほど確率が収束し、チャンピオンと上位5位が高精度で絞り込まれる。リアルタイムデータが蓄積されるほど予測が鋭くなる。

特徴量の大原則
「レース当日に知れる情報」のみ使う

過去の優勝回数など過去バイアスになる統計はXGBoostの特徴量に直接入れない。チームの強さはPhase 2のDNAスコアとして定性的に組み込む役割分担にする。

開発スタイル
最小構成からスタート、段階的に拡張

特徴量はPhase 1の最小セットから始め、追加するたびに精度への影響をアブレーション分析で確認する。「効いた・効かなかった」をデータで判断する。

データ分割戦略

時系列の向きを守った分割により未来データのリークを防ぐ。「1歩前で検証してから本番へ」という原則。

学習データ
〜2024年
約140〜170レース / k-fold交差検証で繰り返し訓練
テストデータ
2025年
24レース / 最後に1回だけ汎化確認
本番
2026年〜
逐次追加・リアルタイム予測
重要ルール：2025年テストデータには原則として最後に1回しか触らない。「2025年の精度が悪かったから修正する」を繰り返すと、気づかないうちに2025年専用モデルが完成してしまう。学習データ内の交差検証でモデルを育てること。
2022年断絶点：グラウンドエフェクト規制変更により、2021年以前と2022年以降は車体の物理特性が根本的に異なる。2019年以前のデータはXGBoostの sample_weight で重みを下げ、2022〜2024年をメインの学習データとして扱う。

LLMの役割設計

LLMは「予測者」ではなく「翻訳者」として使う。定性情報を定量スコアに変換し、XGBoostへの特徴量として注入するのが役割。

LLMに任せていいこと
規制文書のタイプ分類
「空力型 / PU型 / 重量型」への分類
チームの技術的強みの言語解釈
過去データと紐付けた相性スコア生成
サーキット特性の解釈スコア
「モナコ＝市街地＝低速」→ 数値化
リアルタイムデータの文脈解釈
タイヤ状態・戦略意図を数値に変換（Phase 3〜）
LLMに任せてはいけないこと
最終的な順位の直接予測
ハルシネーション・一貫性の欠如リスク
数値データの集計・計算
pandas / numpy で処理するべき領域
「絶対こうなる」という断言
確率的な出力に限定する
データなしでの判断
FastF1の実績数値を渡してから解釈させる
検証方法：① JSON形式で0〜1の数値のみ返すよう出力を固定　② LLMスコア vs 実際の成績の相関係数で妥当性確認　③ スコアあり / なしのアブレーション分析で精度への貢献度をデータで示す

フェーズ別 完成度・精度目標

Phase 1
データ分析 + XGBoost MVP

走行データだけで予測基盤を整える。予選順位をベースラインとし、XGBoostがそれを上回れれば合格。特徴量はまだ少ないため大まかな傾向予測にとどまる。

精度目標
Top-5的中率：40〜50%

MAE：4〜6位以内
  • ベースライン比で改善できること
  • 通常年・乾燥路面を前提
機能完成度
  • FastF1でデータ取得・キャッシュ
  • 特徴量テーブルが作れる
  • XGBoostが学習・予測する
  • Streamlitで順位表・重要度グラフ表示
学習目標
  • pandasの基本操作
  • 特徴量エンジニアリングの考え方
  • XGBoostの学習・推論の流れ
  • 過学習の検出と対策
  • MAE / Top-N 評価指標の理解
Phase 2
レギュレーションスコア統合

LLMで定性情報を数値化し特徴量に追加。規制変更年でも開幕2〜3戦で上位3チームの傾向が出ることがPhase 2の本命ゴール。

精度目標
Top-5的中率：55〜65%
  • Phase 1比で精度改善
  • 2026年開幕序盤でも傾向が出る
  • アブレーション分析で貢献度確認
機能完成度
  • LightRAGでFIA規則PDF解析
  • 規制タイプ分類が数値で出力
  • チームDNAスコアが生成される
  • Phase 1特徴量テーブルに追加
  • 追加前後で精度比較できる
学習目標
  • RAGの仕組みと設計
  • LLMへの構造化プロンプト設計
  • 定性情報の数値化手法
  • アブレーション分析の考え方
Phase 3
ベイズ更新 + モンテカルロ

レースを重ねるほど確率が収束する動的予測を実現。残り5戦でチャンピオン的中率70%以上、MLB勝率グラフのような収束の動きが見えれば完成。

精度目標
チャンピオン的中：70%+（終盤）

Top-5的中率：65〜75%
  • 序盤は幅広・終盤は収束
  • 確率の動的変化が見えること
機能完成度
  • レース後に自動ベイズ更新
  • モンテカルロ1000回シミュレーション
  • チャンピオン確率グラフ表示
  • シーズン進行で確率が収束する
学習目標
  • ベイズ更新の理論と実装
  • モンテカルロ法の原理
  • 確率分布の可視化
  • 不確実性の定量的な扱い方
